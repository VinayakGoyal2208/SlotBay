# SlotBay

Find and reserve verified private parking near Bengaluru metro stations, offices and neighbourhoods.

## Stack

The frontend uses HTML, Tailwind CSS, custom CSS and JavaScript (`.js`). React remains the UI library and TanStack Router manages navigation. Components use React's JavaScript element functions; there are no project TypeScript, TSX or JSX files. Express and MongoDB remain responsible for authentication, documents, listings, booking transactions and administration.

Removing React or replacing the backend with static HTML would require a separate application rewrite. This update preserves the existing architecture and business rules.

## Features

- Drivers: search, maps, date/time and vehicle filters, reservations, booking history, notifications and profile correction requests.
- Owners: verification, listing photos, prices, access hours, capacity, blocked dates and arrival details.
- Administrators: owner/listing review, accounts, disputes, corrections, reports and CSV exports.
- Responsive pages, sign-in companions, scroll animations, reduced-motion support and page-specific search metadata.

Online payments and password recovery are not implemented. Owner approval emails require SMTP configuration.

## Requirements and local setup

Use Node.js **24.x** and MongoDB Atlas or a local MongoDB **replica set**. Booking transactions require a replica set.

1. Run `npm ci` in the folder containing `package.json`.
2. For a new installation, copy `.env.example` to `.env`. Configure `MONGO_URI`, `DATA_ENCRYPTION_KEY`, `SITE_URL` and `VITE_SITE_URL`.
3. For local development, use `http://127.0.0.1:5173` for both URL settings.
4. Run `npm run dev` and open that address. Vite forwards API requests to Express on port 4000.

Generate an encryption key only for a **new** database:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

When upgrading, keep the existing database and encryption key. Never commit `.env`, place secrets in `VITE_` variables, or include credentials in shared archives.

For initial administrator creation, privately supply `ADMIN_EMAIL` and `ADMIN_PASSWORD`, then run `npm run seed:admin`. Remove the seed password afterward. There is no default administrator password.

## Vercel deployment

Use the project folder as the Vercel root. The included `vercel.json` defines:

- Install: `npm ci --include=dev`
- Build: `npm run build:vercel`
- Static output: `dist/static`
- API/page function: `api/handler.js`
- Daily maintenance endpoint: `/api/internal/maintenance`

Set these variables in the appropriate Vercel environment:

| Variable | Value |
| --- | --- |
| `NODE_ENV` | `production` |
| `MONGO_URI` | Existing private MongoDB connection URI |
| `DATA_ENCRYPTION_KEY` | Existing stable 64-character hexadecimal key |
| `SITE_URL` | Public HTTPS origin without a trailing slash |
| `VITE_SITE_URL` | Same origin; available during build |
| `CRON_SECRET` | Private random secret of at least 32 characters |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | Transactional email settings, when enabled |

Keep the existing Vercel environment settings when upgrading. Redeploy after uploading these source changes. Do not upload `.env`, `node_modules` or `.git`. Keep API responses and authenticated HTML private; do not add shared caching to them. Page requests still use Express to retain canonical links, crawler metadata and real 404 responses.

## Responsive layout

The homepage uses a stacked hero through 1100px and a two-column trip-filter grid between 768px and 1100px. Date/time and vehicle inputs can shrink within their cells without escaping the search panel. Phone and wider desktop layouts retain their existing arrangements.

Successful sign-in now opens the role-aware dashboard automatically after a brief confirmation. Registration automatically opens the existing owner or driver profile-completion screen. No confirmation button is required. The How it works page keeps step markers, headings and explanations aligned together at tablet widths (768–1100px).

## Loading improvements

- Converted the nine used bundled images from JPEG/PNG to WebP: **3,979,366 to 1,489,740 bytes**, a **62.6% reduction**. Dimensions and transparency are preserved; lossy compression can introduce small visual differences.
- Removed five unreferenced image assets and the old converted image files.
- Public page HTML no longer waits for MongoDB. APIs, listing metadata and the sitemap still connect when needed.
- Homepage content renders while listing queries run, with existing search/loading states and an error message on failure.
- Hero image preloading/high priority and font preconnections reduce resource discovery delays.
- Vercel serves fingerprinted assets with one-year immutable caching. Existing route splitting and lazy Leaflet loading remain enabled.
- Removed project TypeScript files, configuration, direct type dependencies, unused imports, an unused lint plugin and a stale routing tutorial. Updated server imports, Docker and Vercel bundle paths to JavaScript.

These are local build and regression results, not a measured improvement on the deployed site. Actual load time also depends on Vercel cold starts, MongoDB region, network speed and uploaded listing photos. Uploaded photos remain unchanged.
